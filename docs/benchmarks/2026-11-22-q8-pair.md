# 4B Q4 + 7B Coder Q8: memory residency trial

**Both models stayed loaded, answered short requests sequentially, and completed
a two-minute observation with at least 9.32 GiB available RAM.** This pair fit
the measured Windows desktop session without triggering the two-GiB reserve.

| Setting / result | Observation |
| --- | --- |
| Host | i7-9700, 32 GB RAM, CPU inference, Windows |
| Ollama | 0.40.16 |
| Fast model | `qwen3.5:4b`, Q4 |
| Coding model | `qwen2.5-coder:7b-instruct-q8_0`, confirmed Q8_0 via `/api/show` |
| Coding weights | Approximately 8.1 GB; download/verification took 738.8 seconds |
| Context / threads | 2,048 per model / four inference threads |
| Request concurrency | Sequential across both models, one per model maximum |
| Preload 7B Q8 | 5.13 seconds |
| Preload 4B while retaining 7B | 12.75 seconds |
| Short warm replies | Both returned exactly `READY`, completed with stop reason |
| Residency observation | Full 120 seconds after readiness calls |
| Lowest available RAM | 9.322 GiB |
| Peak owned-process RSS sum | 11.137 GiB, approximate; shared pages can be counted twice |
| Total trial | 145.02 seconds |

The new tag was downloaded explicitly at the user's request. Existing models
were retained. An isolated loopback server used port 11436, with ten-minute
per-request keep-alive. Inventory checks confirmed both exact tags at 2,048
context. The user requested other Ollama sessions be stopped: the separate idle
managed LAN server was stopped, leaving only this trial's server and two runners.
The test server and its runners were stopped afterward; no Ollama processes
were intentionally left running. No work applications were closed.

Earlier 4B + 7B FP16 and 4B + 30B Q4 observations reached the RAM reserve and
stopped. The desktop state differed between trials; these are not controlled
quantization or throughput comparisons. The fresh download also warmed the
filesystem cache, so preload timing is not a cold-disk benchmark.

This is evidence for **brief memory fit and basic API responses**, not coding
accuracy, long prompts, concurrent generation or overnight reliability. The
Q8 pair is a promising lower-memory option for supervised desktop experiments.
No default model routing, personal worker policy or Cursor provider settings
were changed. The existing Windows FP16 lab prompt still targets FP16.

Model reference: [Ollama's exact Q8 tag](https://ollama.com/library/qwen2.5-coder:7b-instruct-q8_0).
For Linux, follow [the Mint setup guide](../linux-mint-4b-30b-setup.md); this Q8
pair would require its own Mint test and deliberate model selection.
